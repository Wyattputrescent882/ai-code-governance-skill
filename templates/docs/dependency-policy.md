# Dependency Policy

本文件定义依赖治理规则。AI 不得自行新增依赖。

如果本文件是在项目中途新增的，先从真实 package 文件和 lockfile 中盘点依赖。下方表格是示例，不代表当前项目已批准事实。

## 已批准依赖

按项目实际情况填写。未知项标记为 `TBD` 或 `needs confirmation`：

| 依赖 | 用途 | 是否唯一方案 |
|---|---|---|
| `dayjs` | 日期处理 | 是 |
| `pinia` | 状态管理 | 是 |
| `zod` | 数据校验 | 是 |
| `lodash-es` | 工具函数 | 谨慎使用 |

## 禁止新增的重复依赖

| 禁止依赖 | 原因 | 替代方案 |
|---|---|---|
| `moment` | 已使用 dayjs | `dayjs` |
| `date-fns` | 避免第二套日期库 | `dayjs` |
| 第二个请求库 | 避免请求层分裂 | `src/services/request.ts` |
| 第二个状态管理库 | 避免状态分裂 | 项目既有 store |

## 新增依赖审批标准

新增依赖前必须说明：

1. 项目中是否已有等价能力。
2. 为什么不能复用已有实现。
3. 自己实现成本是否明显更高。
4. 依赖是否维护活跃。
5. 包体积是否可接受。
6. 是否存在安全风险。
7. 是否会引入第二套方案。
8. 是否已获得人工确认。

## 锁文件规则

未经确认，不允许修改：

- `package.json`
- `package-lock.json`
- `pnpm-lock.yaml`
- `yarn.lock`
- `bun.lockb`

如果任务确实需要新增依赖，AI 必须先停止编码并请求确认。
