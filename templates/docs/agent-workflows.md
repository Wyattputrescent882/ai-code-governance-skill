# Agent Workflows

本文件定义 Coding Agent 的标准工作流。它适用于新项目，也适用于项目中途补充 AI 编码治理。

## 项目中途接入流程

1. 读取项目现有说明、配置、源码目录和规范文件。
2. 盘点真实的组件、hooks/composables、services、stores、utils、types、样式系统和测试命令。
3. 更新 `docs/project-index.md`，只写已确认存在的路径。
4. 更新 `docs/architecture.md`，记录真实分层和权威入口。
5. 更新 `docs/dependency-policy.md`，记录已批准依赖和禁止重复方案。
6. 未确认信息标记为 `TBD` 或 `needs confirmation`。
7. 输出接入报告，不直接把模板示例当成事实。

## 新功能开发流程

1. 阅读项目规则文件。
2. 搜索现有实现。
3. 明确复用方案和最小修改范围。
4. 如果用户要求计划优先，先输出计划并等待确认。
5. 否则实施最小变更。
6. 运行检查。
7. 清理重复逻辑。
8. 输出总结。

## Bug 修复流程

1. 复现或定位问题。
2. 查找相关模块。
3. 判断是否已有错误处理或公共逻辑。
4. 提出最小修复方案；如用户要求直接修复，则继续实施。
5. 添加或更新回归测试，除非项目没有测试基础或成本明显不匹配。
6. 运行检查。
7. 输出原因和修复说明。

## 重构流程

1. 不新增功能。
2. 先列出重复逻辑和架构问题。
3. 给出重构计划。
4. 用户确认后再做大范围重构；小范围安全重构可直接执行。
5. 保持外部行为不变。
6. 运行检查。
7. 输出前后对比。

## 依赖变更流程

1. 说明新增依赖的必要性。
2. 检查现有替代方案。
3. 评估体积、维护、安全风险。
4. 获得人工确认。
5. 修改 package 和 lockfile。
6. 更新 `docs/dependency-policy.md`。

## 禁止流程

- 不读项目规范就编码。
- 不搜索现有实现就新增文件。
- 为同一功能生成多套方案。
- 改不相关文件。
- 检查失败后通过关闭规则解决。
- 把模板示例当作真实项目事实。
